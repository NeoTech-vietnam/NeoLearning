# Agent Office

0.16.1 adds the user's one-off 2026-10-12 rain correction: complete the current rain duration to 60 minutes, subtracting already counted rain, using the next fresh positive measured intensity at the current 2x rise rate. Water caps at 100%. The receipt and corrected water are saved together and retained in subsequent writes, preventing replay on reopen/reload. The correction expires after 30 minutes if no valid intensity arrives; zero/stale measurements do not invent rainfall. The weather bar reports estimated minutes/level added after application. This is an estimate, not historical observed rain.

Version 0.16.0 starts shared background weather feeds after the first Office open in each Nimbalyst run. Closing the panel unsubscribes UI listeners while realtime/forecast polling continues with the existing 5-minute/20-minute quota guards. Live flood water is independent of canvas visibility, pause and reduced-motion settings, and persists to extension-global storage at most once per minute while changing. Reopening resumes the shared level; rain -> dry -> rain grows/drains/grows without resetting at weather transitions. Rain rise is doubled to `0.0001 * mmPerHour` per second; drainage is unchanged. Background ticks use fresh data and cap delayed catch-up to 60 seconds; app closure/system sleep/offline periods are not reconstructed as historical rainfall. Deactivation clears timers and listeners. Demo retains its own canvas model.

Version 0.12.1 removes Demo's 18× water acceleration and the storm/base-rise multipliers. Water rise now follows measured rainfall intensity in mm/h: `level += min(100, intensityMmPerHour) × 0.00005 × activeSeconds`, with level bounded to 0–1. Open-Meteo's mm/15-min amount is multiplied by four for the equivalent hourly rate; Tomorrow.io's mm/h is used directly. Zero/missing intensity adds no water even with a rain/storm weather code. At 2, 8 and 20 mm/h the illustrative level rises by 0.6%, 2.4% and 6% per active minute. Initial puddles grow before the waterline begins at 12% level. Rain density, drop length and animation speed follow the same rate. Demo and live use identical timing; Demo options state their example intensities. Dry weather drains by 1.8 percentage points per minute. These are animation settings, not real flood depths or hydrological predictions.

Version 0.12.0 adds accumulating illustrative water: sustained rain expands puddles, then raises a translucent waterline over the ground and workers. Heavier rain and storms accumulate faster; dry weather drains the water gradually. This is a bounded visual simulation while the scene is open, not a flood measurement or forecast. Water resets on reopening/reset or changing provider/coordinates; changing weather at the same location retains it. Demo previews run saturation/drainage 18 times faster so the effect can be inspected in under a minute. Hidden views, pause, reduced motion and stale observations freeze weather progress; a large frame gap never simulates hours of rain.

Storms now show branching lightning about every four seconds, followed roughly 700 ms later by a sharp synthesized crack and rolling thunder. The sound toggle still defaults to off and requires a user action. Each strike plays once; pausing, reducing motion, hiding the view, stale data, leaving storms or closing the panel stops audio. Volume stays bounded. Fog covers the entire canvas in front of workers with drifting banks; session labels stay above the haze and water. Rain has denser drops and ground splashes. Demo weather previews now include fog and snow.

The current integration still requests only realtime weather. Tomorrow.io's separate [Forecast endpoint](https://docs.tomorrow.io/reference/weather-forecast) can supply hourly forecasts for the next 120 hours; its next-hour minute forecast is premium. This release does not add forecast requests or change the existing realtime request cadence.

Tomorrow.io uses `/v4/weather/realtime`, metric units, rain intensity in **mm/h**, wind converted from m/s to km/h, and basic weather codes including thunderstorm 8000. Day/night is computed from solar elevation at the coordinates and data timestamp. Requests are limited to once per **three minutes** while the panel is mounted, including manual refresh and reloads; Open-Meteo checks every ten minutes. The app persists the next permitted request time and backs off at least an hour on HTTP 429 or rejected credentials. Replacing a key reduces a long error backoff to three minutes. Cache entries are bound to provider and coordinates, with both provider time and fetch time shown. Source timestamps older than thirty minutes are marked stale even if just fetched. No claim is made that each response is a new observation or that rain is detected immediately at a particular street.

A Nimbalyst fullscreen panel opened with the apartment icon in the activity bar. The **Session thật** tab maps up to 80 unarchived sessions from the current workspace to pixel characters on one shared scene. Data refreshes every three seconds while the panel is open. Characters use actual session titles, providers, models, board phases and runtime statuses. The outdoor scene assigns each session a stable, varied job: digging, watering plants, chopping wood or breaking rocks. Active characters share profession regions; idle, waiting and paused characters rest at their individual lower-scene positions. These jobs illustrate activity and do not describe the session's actual task. Click a character to open its actual conversation. Hover shows activity; select a list entry for details, then use **Mở session** to open its conversation.

Characters age with current context usage: **0–<25% trẻ em**, **25–<50% trưởng thành**, **50–<75% trung niên**, **75–100% già có râu**. Both the scene and portraits change height, body shape, hair and beard. Live percentages use `metadata.tokenUsage.currentContext.tokens` divided by `currentContext.contextWindow` (falling back only to `tokenUsage.contextWindow` for capacity). Cumulative token totals are not used. Missing measurements show **Chưa rõ tuổi** instead of an invented percentage. Context compaction can make a character younger again. The inspector shows the measured tokens, capacity and four stages. Jobs remain stable when ages or pages change.

The live adapter requests only `nimbalyst-database-read` and uses a parameterized workspace filter. Activity bubbles use projected metadata from the latest 40 messages per session. The event adapter separately projects lifecycle markers, call IDs, durations, orchestration target IDs and delivery provenance. It extracts only session IDs, queue IDs and message kinds from orchestration arguments/results; message bodies, reasoning text, commands and general tool payloads are never returned. The viewer does not send prompts or write session records. Codex event markers and actual delivery provenance are verified against this installation; Claude-style tool/result markers are covered by fixtures.

Activity bubbles distinguish thinking, tool execution (with its name), answering, generic processing, waiting and idle. Completed reasoning says **Vừa suy nghĩ**; completed tools appear as **Tool gần nhất**, so neither is presented as still running. Concurrent calls match their completion IDs. Runtime idle/waiting states override tool markers, and markers older than 90 seconds fall back to generic processing. Activity-read failures retain ordinary session statuses and show a warning. Session-read failures mark retained data as stale. Unknown states remain unknown.

Recorded `created_by_session_id` and parent relationships produce a **Liên kết session** list and yellow dashed arrows. Branch origins alone are excluded. **Tương tác đã ghi nhận** shows green arrows only when the recipient's prompt provenance records receipt from another loaded workspace session. A `send_prompt` start means sending; a successful queue result means queued; neither alone proves delivery. Received reports and automatic child completion reports are distinguished in the timeline. Historical arrows remain static; a newly received message briefly animates. Selecting a hierarchy or interaction entry focuses its two sessions; **Tất cả session** returns to the full scene. The viewer does not initiate collaboration. Navigation follows the built-in Project Graph's `open-ai-session` event. Database fields and navigation are pinned to this Nimbalyst installation.

The **Timeline** reconstructs recent history when the panel opens and filters by session or event category: handoffs, tools, thinking, or session/answer lifecycle. Tool start/end IDs match across polls and session IDs before calculating durations. Initial reads include the latest 160 messages and latest 40 delivery-provenance inputs per session; subsequent reads consume up to 200 new records per session per poll in ascending order, so bursts continue in following polls. History is capped at 600 normalized events, reserving space for up to 200 delivered handoffs. IDs prevent duplicate events, and read failures retain previous history with a warning. This is a bounded recent-history viewer, not a full transcript archive or playback engine. Updates still poll the Nimbalyst database every three seconds; no Claude hook configuration or Codex log access is needed.

The separate **Demo** tab has four simulated agents starting at different ages and jobs, task assignment, pause/resume, manual step and reset. A context slider lets you try all four ages; automatic steps also advance simulated context. Tasks finish after three seven-second ticks or three manual steps. Demo controls and assignments persist in extension storage; unchanged state is not written on mount. The selected live/demo mode is remembered. Demo tasks never operate real AI sessions. Pause and reduced-motion preferences stop work animations and message pulses.

Artwork is drawn locally with Canvas; no assets or code from Agent Office or Agent Flow are copied. The event normalization approach is inspired by Agent Flow. No model calls or package downloads are needed. React is supplied by Nimbalyst. Run `node tests/characters.integration.mjs` to verify age changes, portraits, paused animation and live context mapping. Live tests navigate existing sessions; demo tests reset only the simulation's own data. Tests do not spawn sessions or send prompts.
